## Overview — structure for the 75 minutes

1. Quick intro to Node's built-in test runner and the repo (10 minutes)
2. Test-first: inspect and run `tests/showSummary.test.js` (15 minutes)
3. Improve `showSummary` formatting and assertions (10 minutes)
4. Implement or review `buyProperty` and `rules` basics (20 minutes)
5. Integration: tie `movePlayer` → tile → `handleTile` and run tests (15 minutes)
6. Wrap-up, homework, and next steps (5 minutes)

---

## Plan and timing

Part 1 — Setup & Test runner intro (10 minutes)

- Objective: make sure `node --test` is understood and runs in this repo
- Actions:
  - Show how to run the test suite: `node --test` (or `npm test` if configured)
  - Explain a single test run for `tests/showSummary.test.js`:
    - `node --test tests/showSummary.test.js`
  - Confirm tests currently failing or passing (observe output)

Part 2 — Test-first exploration: `showSummary` (15 minutes)

- Objective: use a focused test to drive small changes
- Actions:
  - Open `tests/showSummary.test.js` and read assertions (name and money alignment)
  - Run only that test and read output
  - If failing, identify the minimal change to `game/showSummary.js` or tests

Teaching points:
  - Formatting alignment and deterministic ordering (sorting by money)
  - Creating small test utilities (`tests/testUtils.js`) to keep tests readable

Part 3 — Small improvement & refactor (10 minutes)

- Objective: make `showSummary` robust and clear
- Actions:
  - Fix or improve `moneyToString()` and padding logic to satisfy test expectations
  - Ensure tests still pass locally

Part 4 — Property basics (`buyProperty`, `rules`) (20 minutes)

- Objective: implement the minimal `buyProperty` flow and rules dispatcher
- Actions:
  - Review `game/createBoard.js` — ensure properties use `ownerId: null`
  - Implement `game/buyProperty.js` (or review existing) that:
    - Validates `ownerId === null`
    - Validates player has enough `money`
    - Deducts price, sets `tile.ownerId`, and adds id to `player.properties`
  - Create a simple `game/rules.js` with `handleTile(player, tile, players, board)` that:
    - Logs property sale when unowned
    - Calls `payRent` when owned
  - Write one or two small tests around buying (example: buying reduces money and sets ownerId)

Part 5 — Integration + run tests (15 minutes)

- Objective: wire movement → tile handling and keep tests green
- Actions:
  - Ensure `movePlayer()` returns or mutates position consistently and `passStart` money is stable
  - Run the tests for movement, playRound and showSummary (the new tests added in the last commit)
  - Keep changes small and test-driven — fix one failing assertion at a time

Part 6 — Wrap-up and homework (5 minutes)

- Quick recap of what was implemented and why
- Homework (see below)

## Tips & Notes for the Mentor

- Start small: focus on `tests/showSummary.test.js` as the canonical example for test-first workflow.
- Keep refactors local and backed by tests; prefer editing `game/showSummary.js` rather than rewriting the test unless the test is clearly wrong.
- Encourage the student to commit often and use descriptive commit messages (small, test-driven commits).
